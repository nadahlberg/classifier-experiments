Overview

Every reusable piece of markup in this project is a cotton component. <c-name /> resolves to cotton/name.html, dots are folders, and hyphens become underscores. Components at the root of cotton/ are the design-system primitives documented here; anything nested deeper is feature furniture that belongs to one surface.

Each primitive declares its interface with <c-vars>, so every attribute shown below has a default and can be omitted. Attributes the component does not declare — Alpine handlers like @click, aria-*, anything — pass straight through to the underlying element.

Icons

Icons are inline SVGs in the lucide style: a 24×24 viewBox, stroke-width="1.5", round caps and joins, and currentColor so they follow the text color of wherever they sit. There is no icon component — copy the markup from the tile and size it with h-4 w-4 or h-5 w-5. These are the ones the app uses today.

Textarea

A textarea that never scrolls: it measures its content on the next tick and again on every keystroke, so it starts at the height of whatever it was given and grows and shrinks as lines are added and removed. Initial content goes in the slot, like the text between any pair of tags.

Markdown

Renders markdown to styled HTML in the browser, live. It reads source from the surrounding Alpine scope, so anything that keeps a string there can drive it. markdownEditor is the ready-made scope for the common pairing: it seeds source from the textarea inside it and updates on input. Headings, emphasis, links, lists, quotes, tables, rules, and fenced code blocks are supported; the source is escaped first, so it renders markdown and never raw HTML.

It renders into content, the same prose class this page and the article pages use, so a rendered document and a hand-written one are the same markup styled by the same rules.

Headings carry no id unless you pass ids. With it, each one gets a slug, which is what the content layout's table of contents reads — it re-scans whenever the prose changes, so it follows a live preview as you type. That is what you want when the markdown is the page. Embedded in one, it is the wrong thing twice over: the headings would join the host page's table of contents, and a heading like ## Overview would collide with the host page's own anchor. Hence the default, and hence typing a heading into the example below changing nothing on this page.

Dropdown item

The rows inside a dropdown, shown live above. A sub-part of a compound primitive keeps a flat root name — <c-dropdown-item>, not a nested namespace — so the root of cotton/ stays the complete list of primitives and this section stays enforced by the guard test.

Modal

A dialog that teleports to <body>, so it works from inside any stacking context. The trigger slot opens it; escape, the close button, and clicking the backdrop all close it, and the page behind stops scrolling while it's open. Buttons inside the modal can close it with @click="close". On small screens it rises from the bottom edge; on larger ones it scales in at center.

Invite people Send teammates an invitation to join this workspace. They'll get an email with a link that expires in 7 days. Sizes: sm for confirmations, md (the default) for forms, lg for anything with real content. A destructive confirmation is just a small modal with a danger button in the footer.
